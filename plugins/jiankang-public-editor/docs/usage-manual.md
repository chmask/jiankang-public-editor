# 见康公众传播AI主编使用手册

适用版本：`0.1.0`

## 1. 安装与调用

### 公开发布后安装

GitHub `v0.1.0` 发布后，可以执行：

```bash
codex plugin marketplace add chmask/jiankang-public-editor --ref v0.1.0
codex plugin add jiankang-public-editor@jiankang-public-editor
```

安装或升级后新建一个 Codex 任务，让五个 Skill 在干净上下文中加载。这两条命令在公开仓库和 `v0.1.0` Release 建立前只是预告，不能据此声称已经公开可安装。

### 在当前仓库本地安装

先把仓库 Marketplace 加入 Codex，再安装插件：

```bash
codex plugin marketplace add /absolute/path/to/personal-ai-native-site
codex plugin add jiankang-public-editor@personal-ai-native-site
```

### 最简单的调用

只需说明内容和目标，不需要先学习五个 Skill：

```text
$orchestrate-public-communication
把这篇文章处理成适合我的微信公众号发布的版本，保留作者风格，目标是提高收藏和转发：……
```

传播统筹会判断当前阶段，选择一个主 Skill 并执行当前安全阶段，而不是只返回一张推荐表。

以下控制词是提示词约定，不是 Codex API 参数：

| 控制词 | 用途 |
| --- | --- |
| `mode=auto` | 显式采用默认自动判断与执行，通常省略 |
| `mode=plan` | 只给传播方案、顺序和风险，不改正文、不创建外部状态 |
| `skill=<skill-name>` | 强制指定一个专业 Skill，仍保留其安全边界 |
| `保持原结构` | 不移动段落、标题和材料顺序 |
| `不改正文` | 只做策划、发布包装或数据复盘 |

## 2. 它怎样工作

插件采用“传播统筹 + 四个专业 Skill”的结构。一次编辑阶段只使用一个主 Skill：

> 选题立意 → 渠道改编 → 发布包装 → 传播复盘

这不是必须从头走到尾的流水线。已有稳定稿可以直接进入渠道改编；正文不需要修改时可以直接做发布包装；已经发布并有数据时可以直接复盘。

插件可以独立安装和工作。中文作家AI助理是可选的上游专业能力，不是强制依赖。

## 3. 五个 Skill

| Skill | 中文名称 | 什么时候使用 | 默认不会做什么 |
| --- | --- | --- | --- |
| `$orchestrate-public-communication` | 传播统筹 | 不确定当前阶段，或任务涉及多个环节 | 不把所有 Skill 同时用于正文 |
| `$plan-wechat-content` | 选题立意 | 明确账号语境、读者、目标、角度和内容承诺 | 不重写整篇正文 |
| `$adapt-writing-for-wechat` | 渠道改编 | 把稳定内容改编为适合公众号阅读的版本 | 不把文章机械切成一行一句 |
| `$package-wechat-publication` | 发布包装 | 生成标题、摘要、封面文案、文末行动和转发文字 | 不擅自广泛重写正文 |
| `$review-wechat-performance` | 传播复盘 | 根据真实数据和反馈形成谨慎解释与下一轮假设 | 不把一次表现写成确定规律 |

中文名称帮助理解职责；英文名称是实际调用标识。例如，直接做发布包装时调用 `$package-wechat-publication`。

## 4. 推荐工作流

### 从选题开始

```text
$orchestrate-public-communication
这是我的账号定位、目标读者和已有材料。请先判断这个选题是否值得做，给出正文能够兑现的传播角度，不要起草全文。
```

传播统筹会进入“选题立意” `$plan-wechat-content`，输出账号语境、目标读者、本次目标、选题价值、传播角度、读者承诺、正文兑现依据、风险和可验证假设。

### 改编成熟文章

```text
使用 $adapt-writing-for-wechat，采用保守改编模式。保留事实、原意和作者声纹，给我一份可复制清稿，并列出可能改变原意或文学效果的修改。
```

最终正文采用自然段。每段承担相对完整的叙述、说明或论证任务；不把移动端阅读简单理解为一行一句。真正有转折、停顿和强调作用的短段可以保留。

### 只生成发布配套

```text
使用 $package-wechat-publication，不改正文。根据这份稳定稿生成一个主标题、三个备选标题、摘要、封面短文案、文末行动和朋友圈转发文字。
```

标题必须由正文支持并兑现。原题已经准确有力时，可以直接保留，不为了数量强行替换。

### 发布后复盘

```text
使用 $review-wechat-performance。以下是文章、统计窗口、各项真实数据和读者反馈。请区分观察、比较、可能解释和未知，最多提出三项下一轮假设。
```

没有曝光、时间窗口、基线或可比样本时，插件会明确写出缺口，不自行补造。

## 5. 与中文作家AI助理协同

见康公众传播AI主编负责渠道传播，中文作家AI助理负责内容本身。如果文章存在下列上游问题，传播统筹会在相关 Skill 可用时建议或转入一个上游阶段：

- 核心问题、中心判断或结构不成立；
- 材料不能支持关键结论；
- 事实、引语、来源或因果待核验；
- 作者声纹边界不清楚。

例如：

```text
$orchestrate-public-communication
处理这篇公众号文章。如果内容本身有阻断传播的问题，并且中文作家AI助理可用，请先调用最合适的上游 Skill；完成后再返回传播流程。
```

当 `$orchestrate-chinese-writing` 或其专业 Skill 不可用时，插件不模拟、不声称已经完成专业编辑，而是生成“上游编辑交接单”，包括内容用途、目标读者、传播目标、当前阻断、允许修改、禁止改变、待确认事实或来源，以及返回传播流程的条件。

两个插件协同也不会让两个 Skill 同时重写正文。先完成一个上游阶段，再带着稳定稿和风险返回传播流程。

## 6. 标准发布包

发布包装默认可以提供：

1. 一个主标题；
2. 二至四个备选标题及其真实价值；
3. 摘要；
4. 封面短文案；
5. 必要时的正文导语；
6. 正文稳定稿或稳定版本说明；
7. 一个主要文末行动；
8. 朋友圈转发文字；
9. 作者确认项；
10. 一项传播假设。

字段不适用时可以说明理由后省略。发布包完成只代表文字已经准备好，不代表已经上传、创建微信草稿或公开发布。

## 7. 传播复盘

传播复盘固定区分：

- **观察**：真实数据、统计窗口和读者反馈；
- **比较**：与口径相近的账号自身历史基线比较；
- **可能解释**：保留标题、选题、时间、流量来源和读者匹配等竞争解释；
- **未知**：现有数据不能判断的部分；
- **下一轮假设**：可以在下一篇验证的有限改变；
- **验证所需数据**：下一次需要记录的指标和对照。

一次文章的结果不足以证明稳定规律。插件不承诺爆款、阅读量、涨粉或确定的传播效果。

## 8. MCP 与外部发布

当前版本是 **Skill-only 插件**，不提供 MCP Server、Hooks、Apps 或远程后端。Codex 用户安装插件后即可使用，不需要配置 MCP、API Key 或微信公众号凭据。

Skill 负责让 Codex采用专业规则进行判断；MCP 更适合连接数据库、网站和外部服务。当前插件不能作为 MCP 地址被其他客户端直接连接，也不会登录公众号、上传素材、创建微信草稿或公开发布。

网站现有 Influence Engine 可以生成微信公众号预览和草稿，但它与本插件首版保持分层。未来即使增加连接层，也必须先预览并取得本次外部写入授权；工具可用不等于允许发布。

## 9. 安全、隐私与作者主权

作者主权意味着作者保留事实、立场、结构、文风和最终表达的决定权。插件可以提出问题和方案，但不能以“平台需要”为由替作者接受高风险修改。

发生冲突时，优先级为：事实与来源 → 用户本次明确要求 → 作者已确认的立场和作者声纹 → 账号长期定位 → 本次传播目标 → 平台规则 → 通用传播技巧。

插件不得虚构热点、人物、案例、动作、心理、感官、数据、引语、来源、读者反馈或社会共识；不得把相关性写成因果，不得为了标题效果提高论断强度。医疗、健康、法律和财务等高风险内容缺少来源时，标记“待补来源”“作者解释”或“无法由现有材料确认”。

用户提供的稿件和数据只用于当前任务或当前会话中的处理。当前插件没有远程后端和账号数据库，不建立未经作者确认的永久个人档案。若未来连接外部文档、网站或微信公众号，读取、评论、修改、上传、创建草稿和公开发布分别属于不同权限，不能互相推定。

插件不判断文章是否由 AI 生成，不承诺规避检测，不模仿在世作者的可识别风格，也不通过错别字、随意口语和不规则标点模拟真人。

## 10. 能力边界

0.1.0 聚焦微信公众号专业内容。书稿、论文、公文、小说、广告投放、社群运营和全渠道增长不属于首版完整支持范围。书稿编辑优先使用中文作家AI助理；其他体裁可以得到有限建议，但不能强行套用公众号标准。

首版没有账号历史档案、自动数据导入、内容日历、图片生成、微信草稿创建和发布能力。这些功能只有在后续版本真实实现、验证并说明隐私与授权方式后才会进入产品介绍。
