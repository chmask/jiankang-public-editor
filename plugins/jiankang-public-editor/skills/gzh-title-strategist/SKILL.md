# 公众号标题策划

> 改编自 liucongg/liucong-skills 的同名 Skill，Apache-2.0；见 [UPSTREAM.md](UPSTREAM.md)。见康版修改了输出规模、诊断模式、平台路由和历史数据边界。

从文章真实价值中提炼标题，再决定句式与关键词。只处理标题，不改正文，不顺带生成摘要、封面和转发文案，不执行外部发布。

## 输入与任务判断

直接调用本 Skill 即明确公众号语境，默认中文，用户指定目标语言优先。用户显式要求 LinkedIn 等其他平台时，说明本 Skill 的适配范围与冲突，不静默改平台；可指出对应的发布包装入口。泛标题任务未指平台时，传播统筹仍默认 LinkedIn。

使用用户提供的最完整稿件、原标题、目标读者、账号语气和本次目标。材料类型按用户说明判断，不仅因篇幅短就把“正文”改称“摘要”。Word/PDF 仅在对应文档能力确实可用且材料获授权时提取；不能读取时请用户提供正文，不声称已读。只有摘要时标为“基于摘要的暂定标题”，不声称核验全文；只有原标题时可诊断题面，涉及承诺兑现则列出需要的正文材料，不猜写内容。

按本次请求选择一种交付：

- **只诊断**：评价原标题与正文匹配、读者、信息重心和风险；不生成或替换标题。
- **普通优化**：默认三至六个实质不同的候选，用户指定数量优先；原标题合理时可以保留。选一个主标题及至多两个备选，解释取舍。
- **比较已有方案**：只比较用户给出的标题，选题与数量不扩展；未要求新增时不生成其他标题，也不受三至六个的配额影响。只要选一个时只推荐一个。
- **完整标题策略**：用户明确要求完整、多风格或系统策划时，按下文展开；不要把普通标题请求变成十几项作业。
- **标题复盘**：根据所给标题与真实发布数据做谨慎比较，不代替完整传播复盘。

这些是自然语言任务约定，不需要额外 API 参数。少量上下文缺失且不改变主要结果时，说明临时假设后继续；影响承诺或证据强度时暴露缺口。

## 策划与比较

1. 提炼文章类型、目标读者、一个主要判断或成果、最强证据、可交付价值、正文真实出现的实体及其时效依赖。不要为凑字段编造交付物。
2. 生成标题前读取 [内容类型](references/content-types.md)；比较句式、标点或长度时读取 [标题方法](references/title-mechanics.md)。模板只用于启发，不能据此添加亲历、动作、效果或数字；长度是编辑建议，不是微信硬限制。
3. 涉及热词或关键词时读取 [关键词判断](references/heat-research.md)。没有用户提供的可复核数据，不称为当前热词，不主动查询微信指数或用跨平台热度代替微信证据。明确要求外部核验时按可用工具与材料范围另行处理，不假称已核验。
4. 用户提供历史数据，或要求解释上游统计时，读取 [历史统计示例](references/empirical-signals.md)。其中五账号统计是上游自述、未独立复核；不是用户账号基线、当前趋势、推荐算法规则或点击率预测。实际排序用本次内容与用户材料，历史相关性不写成因果。
5. 候选按不同读者动机取舍，不做同一句话的表面替换。每个入选标题说明正文依据与可能牺牲的信息；无依据的承诺不能靠问号保留。
6. 完整策略可按上游分组：四个稳健准确型、四个有语气辨识度的点击型、三个专业型、两个长期型；只有用户账号可复核数据支持时才加三个数据关键词型。材料不足或重复时减少数量。前五名可按一至五分比较点击意愿、事实匹配、人群匹配、差异化和长期价值；注明这是编辑主观比较，不是效果预测。不支持正文的标题先剔除，不靠总分抵消事实风险。

## 事实与作者边界

取舍顺序：正文真实结论 → 读者可获得的具体价值 → 支撑证据与限定 → 强相关关键词 → 节奏和语气。保留作者声音，不为网感强加俚语、反转、感叹号或每题一个金句。

正文无依据时，不添加公司、产品、评测、数字、结果、“官方”“首个”“最强”“开源”或因果效果；不提高确定性、普遍性、疗效、风险或权威强度。小样本主观反馈不是效率或诊疗效果；缺资料时缩小标题承诺，不替作者补造证据。一个标题优先保留一个主承诺。

## 复盘与输出

标题复盘优先比较同账号、相近时期和相似内容，同时看高、低表现样本。区分标题、选题/时机、账号/分发与暂时无法判断；没有可比样本、曝光/打开口径或时间窗口，不归因于某个词或句式，不承诺爆款。

普通优化先给简短判断，再列候选、正文依据与取舍，最后推荐；比较模式只评价已给方案。不要把解释混入可复制标题。只要求标题时诊断不超过三行。完整策略才展开文章诊断、标题策略、分组候选、前五比较、最终推荐与风险。只诊断或只有题面时按前述边界收束，不强行填满这套结构。
