# 上游编辑协同与交接

## 何时使用

只在内容本身的问题会阻断公众号传播工作时使用。不要把中文作家AI助理当作强制依赖，也不要为了展示协同能力而增加不必要的编辑阶段。

## 可用性检查

先检查当前会话可用 Skill 中是否存在 `$orchestrate-chinese-writing` 或更窄的目标 Skill。名称出现才视为可用，不猜测安装路径，不直接读取另一个插件的缓存目录。

可用时，根据阻断类型选择一个上游主 Skill：

| 当前阻断 | 建议上游 Skill |
| --- | --- |
| 核心问题、中心判断、论证或结构 | `$develop-chinese-nonfiction` |
| 已有文字的行文、节奏或段落 | `$revise-chinese-nonfiction` |
| 事实、引语、来源、因果或论断强度 | `$audit-chinese-claims` |
| 作者认可样本与声纹边界 | `$profile-chinese-author-voice` |
| 阶段不明或跨越多个上游问题 | `$orchestrate-chinese-writing` |

目标 Skill 不可用时，不模拟、不声称已经完成专业编辑。生成交接单后，继续完成不依赖该问题的安全部分，或在阻断会影响全部交付时停止。

## 上游编辑交接单

```text
上游编辑交接单
内容用途：微信公众号文章
目标读者：<已知信息；未知时写“未提供”>
传播目标：<本次目标；未知时写“待确认”>
当前阻断：<具体问题及原文位置>
建议主 Skill：<一个可调用名称或“当前环境不可用”>
允许修改：<本次授权范围>
禁止改变：<事实、立场、结构、文风或其他禁区>
待确认事实或来源：<真实缺口；没有则写“无”>
返回传播流程的条件：<怎样才算形成可继续处理的稳定稿>
```

不得把推测写成作者要求，不得把编辑建议写成已经确认的决定。用户没有说明的信息保持未知。

## 返回传播流程

上游阶段完成后，带回：

- 稳定稿或明确的结构决定；
- 未解决的事实、来源和原意风险；
- 作者已经确认、拒绝或暂缓的修改；
- 仍然禁止改变的表达边界。

返回后重新判断传播阶段，不默认继续所有后续 Skill。上游稿尚需作者确认时，不把它包装成已经可以发布的终稿。
