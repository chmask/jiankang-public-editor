# 双平台传播工作流

先按统筹入口确认平台、输出语言与发布形式，再判断阶段。下表保留公众号路由；LinkedIn 对应 plan-linkedin-content、adapt-writing-for-linkedin、package-linkedin-publication、review-linkedin-performance。LinkedIn 发布包装须读取 ../../../references/linkedin-quality.md，执行平台与内容双向检查。

## 极简自动路由

按用户真正需要的交付物判断当前阶段，不按输入篇幅或关键词机械路由：

| 当前状态或请求 | 主 Skill | 本轮交付 |
| --- | --- | --- |
| 读者、目标、传播角度或读者承诺尚不明确 | 选题立意 `plan-wechat-content` | 可由材料兑现的传播方案 |
| 已有稳定稿，需要调整公众号阅读路径 | 渠道改编 `adapt-writing-for-wechat` | 诊断或可复制改编稿 |
| 只需要标题、摘要、封面文案或其他发布组件 | 发布包装 `package-wechat-publication` | 可复制发布包 |
| 已有发布数据或真实读者反馈 | 传播复盘 `review-wechat-performance` | 观察、解释边界与下一轮假设 |

用户同时要求多项工作时，先处理最上游且会改变后续结果的一项。若正文尚不稳定，不能先用大量标题方案掩盖内容问题；若用户明确只要发布组件且正文能够兑现承诺，不扩大为全文改写。

## 上游阻断判断

下列问题会实质影响传播版本时，进入上游编辑交接：

- 核心问题或中心判断无法辨认；
- 章节或文章结构不能支撑承诺；
- 材料不能支持关键结论；
- 关键事实、引语或因果关系待核验；
- 作者声纹边界不明，改编很可能抹平个人表达。

局部标题、开篇、解释密度、段落节奏、阅读提示和文末行动仍属于本插件，不因追求完美而扩大上游范围。

## 复合任务

复合任务给出不超过四步的顺序，然后执行第一个安全阶段。后续每一阶段重新指定唯一主 Skill。默认确认点包括：

- 传播目标或目标读者发生实质变化；
- 改编需要改变核心判断或大幅移动结构；
- 标题承诺超过正文现有支持；
- 上游核验要求降低重要论断强度；
- 修改会显著改变作者声音；
- 操作涉及上传、创建微信草稿或公开发布。

## 外部发布边界

首版只生成可复制发布包，不执行外部发布。即使环境提供网站、浏览器、MCP 或微信公众号工具，也必须先取得本次写入授权，并遵守相应工具的预览和确认流程。用户只要求编辑或策划时，不把创建草稿当成默认下一步。

## 材料不足

缺少账号定位、读者或目标时，先判断是否能采用不会改变核心结果的临时假设。可以安全继续时明确标注假设，不强迫用户填写完整问卷；不同答案会产生实质不同方案时，只询问最关键的一项。
