# 见康公众传播AI主编使用手册

适用版本：`0.4.0`

## 0.4.0 新增：公众号标题策划

新增独立入口 **公众号标题策划** `$gzh-title-strategist`，当前共十一个 Skill。改编自 [liucongg/liucong-skills](https://github.com/liucongg/liucong-skills/tree/19e42a49fbb18bfe496e7d2950754d9d7d68904f/skills/gzh-title-strategist)，保留 Apache-2.0 许可与来源记录，不需要额外后端、MCP 或 API Key。

**最简单：直接贴文章，只处理标题。**

```text
$gzh-title-strategist
只优化这篇公众号文章的标题，不改正文。
目标读者：<读者>；语气：<希望保留的作者语气>。
原标题：<如有>
正文：<文章>
```

默认给三至六个实质不同的方向，说明正文依据，推荐一个主标题和至多两个备选；数量可以自己指定。原题准确有力时可以保留，不保证爆款，不把主观比较当点击率预测。

也可以继续只用传播统筹：

```text
$orchestrate-public-communication
这篇公众号文章只优化标题，给我三个不同方向并推荐一个，不改正文：……
```

它会自动选择“公众号标题策划”，不是整套发布包装。无渠道信息的泛标题请求仍默认 LinkedIn；请说“公众号标题”，或直接用 `$gzh-title-strategist`。

| 你要做什么 | 直接怎么说 | 本轮范围 |
| --- | --- | --- |
| 只判断原标题 | `$gzh-title-strategist 只诊断原标题，不生成新标题：……` | 题面、正文匹配与风险；不换题 |
| 比较已有方案 | `$gzh-title-strategist 比较这三个题目，按正文挑一个：……` | 比较、正文依据与取舍，不补全发布包 |
| 深入策划标题 | `$gzh-title-strategist 做完整标题策略，给多风格候选和前五比较：……` | 展开分组、编辑评分、主标题与备选 |
| 标题数据复盘 | `$gzh-title-strategist 用这些同账号、同窗口数据复盘标题：……` | 区分标题与选题、时机、分发等解释 |
| 标题加摘要、封面等 | `$package-wechat-publication 不改正文，生成整套发布包：……` | 沿用原发布包装；不自动加一轮大型标题策划 |

只有摘要时可以先出暂定方案，但不能声称核验全文；只有原标题时可先看题面，承诺能否兑现仍需正文。没有材料依据，不加“首个”“官方”“最强”、效果数字或作者亲历。历史热词不等于当前热度，更不是微信算法规则。

上游附带五账号历史统计，但未提供可复核的逐篇数据，本项目未独立验证，不把它当你的账号基线或效果承诺。完整策略中的分数只是编辑判断。

下方公开安装命令已固定到 v0.4.0；旧版用户按“从旧版升级”步骤刷新市场和插件，安装后新建对话加载。网页试用暂未加入独立标题入口，需安装 Codex 插件使用。

## 0.3.0 社群语气更新

0.3.0 包含十个 Skill：传播统筹、四个公众号 Skill、四个 LinkedIn Skill，以及 **社群语气适配** `$adapt-social-language`。0.4.0 再增加公众号标题策划，旧调用名不变。

未指定最终发送渠道时默认 LinkedIn，默认英文，简短说明后直接继续。明确公众号则沿用中文默认值；明确指定其他目标语言优先。社群语气适配中，中文提问、中文原稿或“朋友圈文案”本身不指定中文输出；要中文请说“中文朋友圈”或 language=zh。原稿中文不代表公众号，朋友圈与公众号分开。

```text
$orchestrate-public-communication
把下面这段英文改成适合外发的自然表达，保留原意与限定：……
```

以上会默认按 LinkedIn 处理。也可直接调用：

```text
$adapt-social-language
platform=reddit language=en community=<具体社区或你提供的规则>
按这个社区的读者调整措辞，slang=auto；保留项目关联披露，不加推广链接：……
```

`platform` 可选 linkedin、facebook、instagram、reddit、moments（朋友圈）；公众号仍用 wechat。tone、community、slang 是提示词约定，不是 API 参数，也可用自然语言表达。slang=off 不新增俚语，auto（默认）按语境判断，light 可适度轻松但不强加黑话；常规缩约不等于俚语。一个请求可要多渠道独立版本，不要求你逐个调用。

| 渠道 | 文字适配起点 | 需要留意 |
| --- | --- | --- |
| LinkedIn | 专业、具体、可交谈，允许自然缩约 | 职业读者、身份和术语；不套成功学开头 |
| Facebook | 按个人/主页/群组及读者关系调整 | 群组规则与具体目的，不强装熟人 |
| Instagram | caption 对应实际内容和视觉 | 无图不编画面；emoji/标签按需 |
| Reddit | 问题、方法、证据与局限清楚可讨论 | 本地规则、推广限制、AI 内容政策及关联披露 |
| 朋友圈 | 自然克制、重视关系距离 | 默认英文可改中文，不编亲历或朋友评价 |

缩约（we're）、专业简称（B2B）和社区用语（TL;DR、OP）分开判断；不是越多越地道。具体社群“流行词”以用户提供或可核验的近期材料为准；无材料时给通用自然语体并标明待核验。若社区明确禁止这类推广或 AI 内容，不伪装成成员经历绕过规则。

Facebook、Instagram、Reddit、朋友圈本版仅支持文字/语气适配，不表示具备完整渠道策划、指标复盘、账号连接或发布功能。网页试用仍为公众号范围，不随插件升级自动增加社群能力。

## 保留的双平台能力（0.2.x 起）

原有传播统筹、四个公众号 Skill 与四个 LinkedIn Skill 继续保留；加上社群语气适配与独立标题能力，0.4.0 共十一个。公众号原有调用名称保持兼容。LinkedIn 输出英文为默认值，用户可指定其他语言；英文输入本身不决定平台。

| 中文名称 | 直接调用 |
| --- | --- |
| LinkedIn 选题立意 | $plan-linkedin-content |
| LinkedIn 英文改编 | $adapt-writing-for-linkedin |
| LinkedIn 发布包装 | $package-linkedin-publication |
| LinkedIn 传播复盘 | $review-linkedin-performance |

```text
$orchestrate-public-communication
platform=linkedin language=en format=post
将这份中文专业稿改编为英文动态帖，保留限定、证据和我的克制语气。
```

```text
$package-linkedin-publication
format=article 不改正文
根据稳定英文稿准备标题、配套动态帖和必要封面文案，
同时检查 LinkedIn 发布形式与文章能够兑现的承诺。
```

LinkedIn 可用形式：post、article、companion_post、newsletter（仅单期）。控制词是提示词约定，不是 API 参数；直接用自然语言说明同样有效。多平台任务分阶段交付独立稿。0.3.0 起没有渠道信息则默认 LinkedIn，不再为此询问。

英文改编保护语义、术语、跨文化背景、作者声纹和身份真实性。中文稿默认中文解释、英文清稿；列出删减、歧义、身份指代及待确认术语。

发布包装新增平台与内容双向质量标准：正文支持决定标题和开篇的承诺；平台形式和职业读者需求反过来影响组件选择与阅读路径。每次给出“平台要求/建议→正文依据→包装选择→缺口或作者决定”记录。正文需要补证据或实质重组时列出建议并转回改编，不擅自改正文。

精确字符限制、媒体参数与账号功能发布前核验官方资料；策略建议不等于平台硬要求，不承诺算法收益。仅准备文稿，尚无 LinkedIn 账号连接或自动发布。网站现有四种在线适配器仍为公众号范围，本次 Skill 升级不会自动使网页具备 LinkedIn 能力。

下文公众号分支的流程与发布包字段适用于公众号；公共安全、作者主权与外部权限条款适用于所有渠道。安装后需新任务拾取新版。

## 1. 安装与调用

### 公开安装或升级

首次安装：

从固定发布版本安装：

```bash
codex plugin marketplace add chmask/jiankang-public-editor --ref v0.4.0
codex plugin add jiankang-public-editor@jiankang-public-editor
```

从旧版升级时，先移除旧的同名市场来源配置，再添加新标签并刷新插件：

```bash
codex plugin marketplace remove jiankang-public-editor
codex plugin marketplace add chmask/jiankang-public-editor --ref v0.4.0
codex plugin add jiankang-public-editor@jiankang-public-editor
```

移除的是市场来源配置，不是稿件或其他插件。安装或升级后新建一个 Codex 任务，让所安装版本的 Skill 在新上下文中加载。不要只更新市场而忘记更新插件。

### 在当前仓库本地安装

先把仓库 Marketplace 加入 Codex，再安装插件：

```bash
codex plugin marketplace add /absolute/path/to/personal-ai-native-site
codex plugin add jiankang-public-editor@personal-ai-native-site
```

### 最简单的调用

只需说明内容和目标，不需要先学习所有 Skill：

```text
$orchestrate-public-communication
把这篇文章处理成适合我的微信公众号发布的版本，保留作者风格，目标是提高收藏和转发：……
```

传播统筹会判断当前阶段，选择一个主 Skill 并执行当前安全阶段，而不是只返回一张推荐表。

以下控制词是提示词约定，不是 Codex API 参数：

| 控制词 | 用途 |
| --- | --- |
| `mode=auto` | 显式采用默认自动判断与执行，通常省略 |
| `mode=plan` | 只给传播方案、顺序和风险，不改正文、不创建外部状态 |
| `skill=<skill-name>` | 强制指定一个专业 Skill，仍保留其安全边界 |
| `保持原结构` | 不移动段落、标题和材料顺序 |
| `不改正文` | 可做文字诊断、用词建议、策划、发布包装或复盘；不生成改编正文 |

## 2. 公众号流程怎样工作

公众号分支采用“传播统筹 + 五个公众号专业 Skill”的结构。一次编辑阶段只使用一个主 Skill：

> 选题立意 → 渠道改编 → 公众号标题策划（需要时）→ 发布包装 → 传播复盘

这不是必须从头走到尾的流水线。已有稳定稿可以直接进入渠道改编；只要标题时直接进入公众号标题策划，整套组件则做发布包装，不强制先策划标题；已经发布并有数据时可以直接复盘。

插件可以独立安装和工作。中文作家AI助理是可选的上游专业能力，不是强制依赖。

## 3. 公众号分支的六个 Skill（含统筹）

| Skill | 中文名称 | 什么时候使用 | 默认不会做什么 |
| --- | --- | --- | --- |
| `$orchestrate-public-communication` | 传播统筹 | 不确定当前阶段，或任务涉及多个环节 | 不把所有 Skill 同时用于正文 |
| `$plan-wechat-content` | 选题立意 | 明确账号语境、读者、目标、角度和内容承诺 | 不重写整篇正文 |
| `$adapt-writing-for-wechat` | 渠道改编 | 把稳定内容改编为适合公众号阅读的版本 | 不把文章机械切成一行一句 |
| `$gzh-title-strategist` | 公众号标题策划 | 只诊断、改写、比较或排序公众号标题 | 不改正文，不自动补成发布包 |
| `$package-wechat-publication` | 发布包装 | 生成标题、摘要、封面文案、文末行动和转发文字 | 不擅自广泛重写正文 |
| `$review-wechat-performance` | 传播复盘 | 根据真实数据和反馈形成谨慎解释与下一轮假设 | 不把一次表现写成确定规律 |

中文名称帮助理解职责；英文名称是实际调用标识。例如，直接做发布包装时调用 `$package-wechat-publication`。

## 4. 推荐工作流

### 从选题开始

```text
$orchestrate-public-communication
这是我的微信公众号定位、目标读者和已有材料。请为公众号判断这个选题是否值得做，给出正文能够兑现的传播角度，不要起草全文。
```

传播统筹会进入“选题立意” `$plan-wechat-content`，输出账号语境、目标读者、本次目标、选题价值、传播角度、读者承诺、正文兑现依据、风险和可验证假设。

### 改编成熟文章

```text
使用 $adapt-writing-for-wechat，采用保守改编模式。保留事实、原意和作者声纹，给我一份可复制清稿，并列出可能改变原意或文学效果的修改。
```

最终正文采用自然段。每段承担相对完整的叙述、说明或论证任务；不把移动端阅读简单理解为一行一句。真正有转折、停顿和强调作用的短段可以保留。

### 只生成发布配套

```text
使用 $package-wechat-publication，不改正文。根据这份稳定稿生成一个主标题、三个备选标题、摘要、封面短文案、文末行动和朋友圈转发文字。
```

标题必须由正文支持并兑现。原题已经准确有力时，可以直接保留，不为了数量强行替换。

### 发布后复盘

```text
使用 $review-wechat-performance。以下是文章、统计窗口、各项真实数据和读者反馈。请区分观察、比较、可能解释和未知，最多提出三项下一轮假设。
```

没有曝光、时间窗口、基线或可比样本时，插件会明确写出缺口，不自行补造。

## 5. 与中文作家AI助理协同

见康公众传播AI主编负责渠道传播，中文作家AI助理负责内容本身。如果文章存在下列上游问题，传播统筹会在相关 Skill 可用时建议或转入一个上游阶段：

- 核心问题、中心判断或结构不成立；
- 材料不能支持关键结论；
- 事实、引语、来源或因果待核验；
- 作者声纹边界不清楚。

例如：

```text
$orchestrate-public-communication
处理这篇公众号文章。如果内容本身有阻断传播的问题，并且中文作家AI助理可用，请先调用最合适的上游 Skill；完成后再返回传播流程。
```

当 `$orchestrate-chinese-writing` 或其专业 Skill 不可用时，插件不模拟、不声称已经完成专业编辑，而是生成“上游编辑交接单”，包括内容用途、目标读者、传播目标、当前阻断、允许修改、禁止改变、待确认事实或来源，以及返回传播流程的条件。

两个插件协同也不会让两个 Skill 同时重写正文。先完成一个上游阶段，再带着稳定稿和风险返回传播流程。

## 6. 标准发布包

发布包装默认可以提供：

1. 一个主标题；
2. 二至四个备选标题及其真实价值；
3. 摘要；
4. 封面短文案；
5. 必要时的正文导语；
6. 正文稳定稿或稳定版本说明；
7. 一个主要文末行动；
8. 朋友圈转发文字；
9. 作者确认项；
10. 一项传播假设。

字段不适用时可以说明理由后省略。发布包完成只代表文字已经准备好，不代表已经上传、创建微信草稿或公开发布。

## 7. 传播复盘

传播复盘固定区分：

- **观察**：真实数据、统计窗口和读者反馈；
- **比较**：与口径相近的账号自身历史基线比较；
- **可能解释**：保留标题、选题、时间、流量来源和读者匹配等竞争解释；
- **未知**：现有数据不能判断的部分；
- **下一轮假设**：可以在下一篇验证的有限改变；
- **验证所需数据**：下一次需要记录的指标和对照。

一次文章的结果不足以证明稳定规律。插件不承诺爆款、阅读量、涨粉或确定的传播效果。

## 8. MCP 与外部发布

当前版本是 **Skill-only 插件**，不提供 MCP Server、Hooks、Apps 或远程后端。Codex 用户安装插件后即可使用，不需要配置 MCP、API Key 或微信公众号凭据。

Skill 负责让 Codex采用专业规则进行判断；MCP 更适合连接数据库、网站和外部服务。当前插件不能作为 MCP 地址被其他客户端直接连接，也不会登录公众号、上传素材、创建微信草稿或公开发布。

网站现有 Influence Engine 可以生成微信公众号预览和草稿，但它与本插件首版保持分层。未来即使增加连接层，也必须先预览并取得本次外部写入授权；工具可用不等于允许发布。

## 9. 安全、隐私与作者主权

作者主权意味着作者保留事实、立场、结构、文风和最终表达的决定权。插件可以提出问题和方案，但不能以“平台需要”为由替作者接受高风险修改。

发生冲突时，优先级为：事实与来源 → 用户本次明确要求 → 作者已确认的立场和作者声纹 → 账号长期定位 → 本次传播目标 → 平台规则 → 通用传播技巧。

插件不得虚构热点、人物、案例、动作、心理、感官、数据、引语、来源、读者反馈或社会共识；不得把相关性写成因果，不得为了标题效果提高论断强度。医疗、健康、法律和财务等高风险内容缺少来源时，标记“待补来源”“作者解释”或“无法由现有材料确认”。

用户提供的稿件和数据按当前任务授权处理。本插件没有独立远程后端和账号数据库，不另建未经作者确认的永久个人档案；Codex 宿主和所选模型服务的数据处理规则仍各自适用。若未来连接外部文档、网站或微信公众号，读取、评论、修改、上传、创建草稿和公开发布分别属于不同权限，不能互相推定。

插件不判断文章是否由 AI 生成，不承诺规避检测，不模仿在世作者的可识别风格，也不通过错别字、随意口语和不规则标点模拟真人。

## 10. 能力边界

0.4.0 保留微信公众号、LinkedIn 专业内容能力和多社群文字适配，新增独立公众号标题策划。LinkedIn 支持 Newsletter 单期，不包括订阅体系运营。Facebook、Instagram、Reddit、朋友圈没有完整策划、发布或绩效模型。书稿、论文、公文、小说、广告投放、社群运营和全渠道增长不属于完整支持范围。书稿编辑优先使用中文作家AI助理；英文原稿不交由中文专用 Skill 冒充英文专业审校。其他体裁可以得到有限建议，但不能强行套用渠道标准。

首版没有账号历史档案、自动数据导入、内容日历、图片生成、微信草稿创建和发布能力。这些功能只有在后续版本真实实现、验证并说明隐私与授权方式后才会进入产品介绍。
